# G98 云手机 · 知识总汇（2026-11-22）

> 本文把 2026-11-18 至 2026-11-22 在 BDY G98 板子上积累的运行形态、属性伪装、GPU、相机、风控、VM 试验和踩坑集中记录下来。
> 旧文档保留细节：`G98-踩坑全记录.md`（逐轮记录）、`G98-运维手册.md`（操作）、`HANDOFF.md`（11-19 交付快照）、`locked-image.md`（SELinux/locked 镜像）、`m7-container.md`（m7 单页说明）。

## 1. 一句话总结

板子最终只跑 **m7 一台 redroid 容器**：宿主 Mali-G610 通过 panthor 提供 GPU 硬渲，双路虚拟相机可用，build/flavor/fingerprint/verified boot 等属性按 Xiaomi 13（houji）真机值伪装，`com.g98.riskcheck` 风险分 0/100。VM 线（qemu-system-aarch64）已停用，只保留 qcow2 备份；它无法提供 GPU 硬渲和摄像头，且属性伪装受 `/dev/vda`、SELinux 限制。

## 3. 运行形态演进

### 3.1 旧方案：6 台 redroid 容器（2026-11-19）

- 容器 m1–m6，镜像 `g98/redroid-panthor-rt:13`，数据目录 `/srv/redroid/m1`–`m6`。
- ADB 端口 5555–5560；`service.adb.tcp.port` 重启会丢，需要脚本恢复。
- 相机链路：v4l2loopback + `camera.redroid.so` + camera provider 2.4 legacy + mediamtx（WebRTC 8889 / HLS 8888 / RTSP 8554）。
- 6 台满载内存约 13–15GB，lmkd 经常杀 App；这是后来转向单台 m7 + VM 试验的背景。

### 3.2 VM 方案（2026-11-21）

- 3 台 `qemu-system-aarch64` VM（vm1–vm3），KVM + 板载内核，目的主要是绕开 redroid 共享内核/共享 SELinux 的限制。
- 关键参数：`-machine virt,gic-version=3 -accel kvm -cpu host -smp 4 -m 6144`，`-kernel /boot/vmlinuz-6.18.48-ophub`，`-drive file=/root/vm/vmN.qcow2`，`-device virtio-gpu-pci`。
- 能启动 Android 13、adb 端口 hostfwd 5555–5557；但 QEMU 构建没有 `virtio-gpu-gl-pci`，也没有 virglrenderer，guest 只有 ANGLE/pastel 软渲。
- guest 没有 `/dev/video*`，没有 `/lib/modules`，摄像头无路径；因此 VM 无法满足 GPU 硬渲 + 摄像头两个核心需求。
- 2026-11-22 已停用：`systemctl disable --now g98-vm@1.service`，qemu 进程 0；vm1–vm4 的 qcow2 仍保留，可回滚查看。

### 3.3 当前方案：m7 单容器（2026-11-22 起）

- 镜像：`g98/redroid-panthor-rt:13-mt6983-camfix-v5`（image id `d952d822fec3`，1.84GB）。
- systemd：`g98-m7.service`（oneshot, RemainAfterExit=yes）+ `g98-m7-watch.timer`（每 60s 检查容器，退出则重启服务）。
- 启动脚本：`/srv/redroid/m7-start.sh`；看门狗：`/srv/redroid/m7-watch.sh`。
- 结果：GPU Panfrost、双路相机 Back/Front、属性真机化、riskcheck 0/100；内存远低于 3 台 VM。

## 4. m7 容器细节

### 4.1 启动参数要点

```bash
docker run -d --name m7 --privileged --security-opt label=disable --cap-add SYS_NICE --entrypoint /init \
  -v /srv/redroid/camcfg/cam0-external_camera_config.xml:/vendor/etc/external_camera_config.xml:ro \
  -v /srv/redroid/m7:/data \
  --device /dev/dri --device /dev/video14:/dev/video10 --device /dev/video15:/dev/video11 \
  g98/redroid-panthor-rt:13-mt6983-camfix-v5 \
  qemu=1 androidboot.hardware=mt6983 androidboot.verifiedbootstate=green androidboot.flash.locked=1 \
  androidboot.veritymode=enforcing androidboot.selinux=enforcing \
  ro.hardware.gralloc=g98 ro.hw_timeout_multiplier=10 \
  ro.product.model=23127PN0CC ro.product.brand=Xiaomi ro.product.manufacturer=Xiaomi \
  ro.product.device=houji ro.product.name=houji ro.build.type=user ro.build.tags=release-keys \
  ro.build.fingerprint=Xiaomi/houji/houji:13/TKQ1.221114.001/V14.0.9.0.TMCCNXM:user/release-keys
```

**必须 `--entrypoint /init`**：基础镜像的 Entrypoint 自带 `["/init","qemu=1","androidboot.hardware=redroid"]`；不覆盖时 Docker 会把镜像 Entrypoint 和 Cmd 拼起来，`androidboot.hardware` 仍是 redroid，属性全废。

### 4.2 镜像派生链

`g98/redroid-panthor-rt:13` → `...:13-camfix`（保留 m6 的 camera provider 2.4 legacy + camera.redroid.so）→ `...:13-mt6983` → `...:13-mt6983-camfix` → `...:13-mt6983-camfix-v4` → **v5**。

- v4：补 `ro.debuggable=0`、`ro.adb.secure=1`、`ro.crypto.state=encrypted`、`ro.product.board=houji`，启动参数补 verified boot / selinux。
- v5：在 v4 基础上把 `camera.redroid.so` 的 per-id facing 补丁（back/front）和最终相机验证固化；当前 m7 使用 v5。
- 制作方式：`docker commit`；redroid 镜像没有 `/bin/sh`，Dockerfile 的 `RUN` 不能用。

### 4.3 必须补齐的 HAL 同名模块

`ro.hardware=mt6983` 后，Android `hw_get_module()` 会按 `ro.hardware` 找模块：

```bash
/system/bin/cp -f /vendor/lib64/hw/hwcomposer.redroid.so /vendor/lib64/hw/hwcomposer.mt6983.so
/system/bin/cp -f /vendor/lib64/hw/camera.redroid.so     /vendor/lib64/hw/camera.mt6983.so
```

缺 `hwcomposer.mt6983.so` 时 SurfaceFlinger 报 `failed to open framebuffer device: No such file or directory`；缺 `camera.mt6983.so` 时相机 0 路。这是改 `ro.hardware` 最容易漏的一步。

### 4.4 属性补丁位置

- `/system/build.prop`：build.id、flavor、description、fingerprint、type、tags、security_patch 等。
- `/vendor/build.prop`：`ro.hardware=mt6983`、`ro.product.board=houji` 等厂商字段。
- `ro.hardware` 的默认值来自 init 二进制；本镜像在 `/system/bin/init` 文件偏移 **0x18FB2（十进制 102322）** 把字符串 `unknown` 改成 `mt6983`+NUL。
- 启动参数 `androidboot.*` 负责 `ro.boot.*`；`ro.boot.hardware` 也会随 `androidboot.hardware` 变。

## 5. GPU 硬渲

m7 的 GPU 链路：`/dev/dri` → panthor → gralloc.g98 → `ro.hardware.egl=mesa` → `ro.hardware.vulkan=panfrost`。

验证：

```bash
docker exec m7 dumpsys SurfaceFlinger | grep -i -E 'GLES|Mali|Panfrost'
# 期望类似：GLES: Mesa, Mali-G610 MC4 (Panfrost), OpenGL ES 3.1 Mesa 26.3.0-devel
```

关键点：

- 必须是容器，不是 VM；QEMU 10.0.13 没有 `virtio-gpu-gl-pci`，宿主也没有 virglrenderer，VM 内只能 ANGLE/pastel 软渲。
- `ro.hardware.gralloc=g98`、`ro.hardware.egl=mesa`、`ro.hardware.vulkan=panfrost` 三项要同时正确。
- 改 `ro.hardware` 后必须补 `hwcomposer.<hardware>.so`，否则 SurfaceFlinger 崩。

## 6. 相机链路（m7）

### 6.1 数据流

```text
宿主 ffmpeg（testsrc2 / smptebars，640x480 YUV420P）
  → /dev/video14、/dev/video15（v4l2loopback）
  → camera.redroid.so（V4L2CameraHAL，读 vendor.camera.redroid.nodes）
  → camera provider 2.4 legacy
  → cameraserver
  → camtest / g98cam2
```

`m7-start.sh` 每次启动会杀掉旧 ffmpeg，再启动：

```bash
/root/ffmpeg -re -f lavfi -i testsrc2=size=640x480:rate=30 -pix_fmt yuv420p -f v4l2 /dev/video14
/root/ffmpeg -re -f lavfi -i smptebars=size=640x480:rate=30 -pix_fmt yuv420p -f v4l2 /dev/video15
```

### 6.2 节点与权限

- Docker `--device /dev/video14:/dev/video10` 的改名在 Android ueventd 重建 `/dev` 后**不生效**；容器内 `video10` 仍可能指向宿主 video10。
- 正确做法：直接把宿主 `video14/15` 映射进容器，设置 `vendor.camera.redroid.nodes=/dev/video14,/dev/video15`，让 HAL 使用这两个节点。
- 容器内必须 `chmod 666 /dev/video10 /dev/video11 /dev/video14 /dev/video15`；否则 cameraserver（uid 1047）打不开，报 `Permission denied`。
- 同一 v4l2loopback 节点同一时刻只能一个进程打开；测试前 `am force-stop com.g98.camtest`，并同时重启 provider + cameraserver。

### 6.3 provider 版本

- rt:13 基础镜像只有 2.7 external provider；m6 的 camera 修复文件系统里有 2.4 legacy provider + `camera.redroid.so`，所以用 m6 `docker commit` 得到 camfix 基。
- 2.7 external 注册会报 `Service android.hardware.camera.provider@2.7::ICameraProvider/external/0 must be in VINTF manifest`；手工往 manifest 加条目又会报 `Duplicated interface entry` / `Duplicated manifest.hal entry` / `Duplicated major version`。结论：**不要走 2.7 external，走 2.4 legacy**。
- 2.4 legacy provider 启动后 `dumpsys media.camera` 应显示 `Number of camera devices: 2`、Facing Back/Front。

### 6.4 HAL 源码补丁（已入库）

`hal/camera3_4/v4l2_metadata_factory.*` 和 `v4l2_camera.cpp` 已改成按 camera id 分配 facing：

```cpp
// v4l2_metadata_factory.cpp
ANDROID_LENS_FACING,
id == 0 ? ANDROID_LENS_FACING_BACK : ANDROID_LENS_FACING_FRONT
```

编译产物 `camera_v7.so`（676,832 B）部署到 `/vendor/lib64/hw/camera.redroid.so` 和 `camera.mt6983.so`。

### 6.5 格式与限制

- `camera.redroid.so` 的 `setupStreams` 先尝试 YUV420；v4l2loopback 生产者若不是 `yuv420p` 会 `S_FMT failed: Device or resource busy` / `-ENODEV`。
- `camera.redroid.so` 单流、单格式；多流必须同宽高，复杂 preview+JPEG 组合可能 `Unsupported set of inputs/outputs`。
- camtest（`com.g98.camtest`）用单路 `ImageReader` YUV_420_888 640x480 验证最稳。
- g98cam2（`com.g98.cam2`）单 JPEG 流可用；stock AOSP `com.android.camera2` 与 provider 2.4/camera3.3 兼容性未打通，会报 `Can't connect to the camera`。

## 7. 风控 App（riskcheck）与伪装

包名 `com.g98.riskcheck`，源码 `riskcheck/src/com/g98/riskcheck/RiskAudit.java`。主要检查：

- **属性**：`ro.debuggable`、`ro.secure`、tags `test-keys`/`dev-keys`、`ro.build.type=userdebug/eng`、`ro.kernel.qemu`、`ro.boot.qemu`、hardware 含 redroid/goldfish/ranchu/qemu/vbox/virtual、fingerprint/flavor 含 redroid/generic/emulator、`verifiedbootstate=green`、`flash.locked=1`、`veritymode=enforcing`、`crypto.state=encrypted`。
- **Root**：常见 su 路径、`command -v su`、uid=0、`/proc/mounts` 含 magisk/worker、root 管理 App 包名。
- **模拟器**：Build 字段、props 串（redroid/goldfish/ranchu/qemu/angle/pastel/lvp/swiftshader/vbox）、qemu 文件和 HAL 文件、`/proc/cpuinfo`、`/proc/version`、DMI/devicetree、`/sys/block` 的 vd/sd/virtio。
- **容器**：`/proc/1/cgroup`/`/proc/self/cgroup` 含 docker/lxc/kubepods/containerd/podman/libpod；`/proc/version` 含 redroid/qemu/wsl；`/proc/cmdline` 含 androidboot.hardware=redroid/redroid/docker；root 挂载含 overlay//dev/vda//dev/sda/virtio/9p/fuse；`/proc/1/environ`。
- **SELinux**：`ro.boot.selinux`、`/sys/fs/selinux/enforce`、`getenforce`、`/proc/self/attr/current`、`/sys/fs/selinux/policy` 大小；`enforce=0`/`permissive`/`disabled` 即 RISK，domain `u:r:kernel:s0`/`HACKED`/`unlabeled`/空 也 RISK。
- **调试**：`Settings.Global adb_enabled=1`。

### 7.1 m7 的伪装文件

```text
/fake/enforce  内容 "1"
/fake/block    空目录（bind 到 /sys/block，隐藏 sda/vd）
/fake/attr     内容 "u:r:untrusted_app:s0"
/fake/mounts   第一行 "/dev/block/dm-0 / ext4 rw,seclabel,relatime 0 0" + 原 /proc/mounts 去掉第一行
```

`m7-start.sh` 用 `docker exec` 把 `/fake/enforce` 绑到 `/sys/fs/selinux/enforce`、`/fake/block` 绑到 `/sys/block`；`risk-watch.sh` 每 20ms `pidof com.g98.riskcheck`，发现新 pid 就把 `/fake/attr` 绑到 `/proc/<pid>/attr/current`、`/fake/mounts` 绑到 `/proc/<pid>/mounts`。

### 7.2 结果与限制

- riskcheck 实测：**score 0/100，高危 0、中危 0、低危 0**，结论“未发现明显风险”。
- 这不是真 SELinux enforcing：`getenforce` 仍可能显示 `Disabled`，`/sys/fs/selinux/policy` 也没有真的加载。只是让 riskcheck 读到的 `enforce` 字符串为 `1`、进程 domain 为 `u:r:untrusted_app:s0`。
- 对使用 TEE/AVB/硬件密钥的 App，这套伪装不能替代真机；身份认证类 App 仍可能弹风险。

## 8. VM 线复盘

### 8.1 为什么做 VM

redroid 容器共享宿主内核，SELinux policy 全宿主一份，难以做到每实例独立 enforcing；VM 有独立内核，理论上有独立 selinuxfs。

### 8.2 能跑通的部分

- 板载内核 `6.18.48-ophub` 可直接作为 qemu `-kernel`；`CONFIG_ANDROID_BINDER_IPC=y`、`BINDERFS=y`。
- `qemu-system-aarch64` 10.0.13 + KVM 可用；Android 13 guest 能启动，`sys.boot_completed=1`。
- `build.prop` 可改 flavor/id/fingerprint/verified boot；`/system/bin/init` 偏移 102322 的 `unknown` 改成 `mt6983` 可改 `ro.hardware`。

### 8.3 为什么放弃

- **GPU**：qemu 没有 virtio-gpu-gl/virgl；Mali 是 platform device，不能 PCI 直通；guest 只能软渲。
- **摄像头**：guest 无 `/dev/video*`、无 `/lib/modules`、无法 insmod；宿主是 MIPI 非 USB UVC，qemu 无 UVC 模拟。
- **属性**：根挂载 `/dev/vda`、`/sys/block` 的 vd 设备会触发 riskcheck；SELinux 仍 `Disabled`；写 `ro.crypto.state=encrypted` 会导致 `vdc cryptfs enablefilecrypto Failed` 无限重启，不能伪造。
- 结论：VM 只能做 Android 启动/属性试验，不能满足硬件渲染和相机；2026-11-22 已停用。

### 8.4 qemu-nbd 改镜像流程（复盘）

```bash
# 先杀 qemu（否则 qcow2 被锁）
qemu-nbd --connect=/dev/nbd0 --format=qcow2 /root/vm/vm1.qcow2
mount -t ext4 /dev/nbd0 /mnt/vm1
# 改 /mnt/vm1/system/build.prop 或 /mnt/vm1/system/bin/init
sync; umount /mnt/vm1; qemu-nbd --disconnect /dev/nbd0
```

回滚：`/root/vm/init.bak` 是原始 init；`/root/vm/init.orig` 是原 `/init` 符号链接。

## 10. 通用踩坑清单

- redroid 不支持 `wrap.` 前缀的 LD_PRELOAD 注入。
- 需要 `ro.hw_timeout_multiplier=10`，否则 FUSE 挂载失败、相机 App 崩。
- `docker -p` 在本板不可用（iptables 缺 nf_tables tcp/DNAT），用 bridge IP + `service.adb.tcp.port`。
- `service.adb.tcp.port` 重启会丢，需 `setprop` + `stop/start adbd`。
- `screencap` 可能阻塞约 60 秒，脚本要给 timeout。
- v4l2loopback 节点同一时刻只能一个进程打开；换生产者后同时重启 provider 和 cameraserver。
- `docker cp` 不能直接读 `/sdcard`（FUSE），走 `/data/media/0/...` 或 `/data/local/tmp`。
- `docker exec` 嵌套引号容易被吞；复杂命令写脚本再 `sh /tmp/x.sh`。
- Docker `--device /dev/video14:/dev/video10` 的改名会被 Android ueventd 覆盖；直接映射并设置 `vendor.camera.redroid.nodes`。
- 改 `ro.hardware` 必须补 `hwcomposer.<hw>.so`、`camera.<hw>.so` 等同名模块。

## 12. 限制与后续

- 无真实摄像头传感器：当前是 ffmpeg 测试图；要接真实画面，把 `/dev/video14/15` 的生产者换成 UVC/手机推流/桌面采集。
- SELinux/root 是进程级伪装，不是真 enforcing，也不等于 TEE/AVB 真机。
- stock AOSP Camera2 兼容性未打通；业务 App 用 camtest/g98cam2 验证。
- Docker 镜像只在本机，未推 registry；迁移用 `docker save g98/redroid-panthor-rt:13-mt6983-camfix-v5 -o m7-v5.tar` 再 `docker load`。
- 多开容器前先确认内存、v4l2loopback 节点独占和相机 provider 端口。
